# A standing em-dash probe for every placeholder or punctuation rule
- Source: BUG-20260819-punctuated-rationale-buys-an-a; GATE-review-legit-short-rationale-passes; J-review-round-seal
- Why automate: regression-prone across features, not within one — this repo has now paid for `mawk`'s byte orientation twice: once in `head_of()` of `tests/check-todo.sh`, where a negated class over a multibyte character made the sensor fail open on ordinary punctuation, and once here, where `—` is a legitimate rationale that any `[[:punct:]]`-shaped fix would swallow. The next such rule will be written by someone who has not read either story.
- Suggested layer: unit (a shared probe helper the placeholder rules call), invoked from `tests/check-gates.sh`
- Spec sketch: assert that the em dash (`E2 80 94`), the en dash, the hyphen-minus, `clean` and `n/a` are all ACCEPTED, while the placeholder set and its punctuated variants are refused — one table, both directions, so a rule that refuses everything fails it as loudly as one that refuses nothing.
- Status: proposed — partially satisfied in place by F3 (`272cb91`), which made "remove the `—` exception" one of 13 adversarial degradations of the `gate_REVIEW` assertion. That covers this rule. The entry stays open because it asks for a *shared* probe the NEXT such rule inherits, and the next author will not have read this story: F3 also refused `FIXME` and `XXX` with no world proving it, which is the same gap reappearing one commit later.
